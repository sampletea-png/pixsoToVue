# 组件语义推断规则

Pixso 设计者不按组件思维画图：输入框可能只是「矩形 + 文本」，按钮可能只是「圆角矩形 + 居中文字」。**生成代码前必须先为每个区域/节点推断语义角色**，再写对应的 Vue 结构。

## 推断方法

对每个区域，结合三份证据（缺一不可）：

1. **DSL 结构特征**（`regions/*.dsl.json`）：尺寸、圆角、边框、子节点组合。
2. **截图视觉**（对应画板 PNG 中的该区域）：对齐、层级、视觉强调。
3. **文本内容**：占位提示语、按钮文案、label 命名。

## 结构特征 → 语义组件对照表

| DSL 特征 | 推断 | Vue 实现 |
| --- | --- | --- |
| 矩形（高 28–48px，宽明显大于高）+ 内嵌灰色提示文本，可能有边框/圆角 | 输入框 | `<input>` 或封装 `<FormInput>`，提示文本 → `placeholder` |
| 同上但右侧有下拉箭头/三角 | 下拉选择 | `<select>` 或自定义 `Dropdown` |
| 圆角矩形 + 居中短文本（2–6 字），背景色强调 | 按钮 | `<button>`，按背景色分 primary/secondary/danger |
| 纯文本短句 + 无背景，颜色为主题色 | 文字按钮/链接 | `<a>` / `<button class="link">` |
| 小正方形 + 对勾/无对勾 + 右侧文本 | 复选框 | `<input type="checkbox">` |
| 圆形外框 + 内圆点 + 文本 | 单选框 | `<input type="radio">` |
| 细长矩形（宽 ≈ 容器，高 1–2px） | 分隔线 | `<hr>` 或 border |
| 同构子项纵向/横向重复 ≥3（每项含标题+描述+缩略图等） | 列表 | `v-for` + 数据驱动，**禁止静态复制** |
| 网格状同构卡片 | 卡片列表 | `v-for` + CSS grid/flex |
| 顶部通栏：logo + 若干等距文本项 | 导航栏 | `<nav>` + router-link |
| 左侧窄栏纵向菜单项（图标+文本） | 侧边栏菜单 | `<aside>` + 菜单组件 |
| 底部通栏多个图标+文字（移动端） | TabBar | 公共 `TabBar` 组件 |
| 等距排列的短文本组，其中一个有下划线/高亮 | Tab 页签 | Tabs 组件 + `v-model` 激活态 |
| 大矩形遮罩 + 居中浮层（标题+内容+按钮组） | 弹窗/对话框 | `Dialog` 组件 + `v-model:visible` |
| 头像圆形 + 名称 + 次要文本 | 用户信息块 | 语义化结构，头像 `<img>` 圆形 |
| 矩形内多根柱/折线/饼图占位 | 图表 | 占位 `<div class="chart">` + TODO（或按用户要求引入图表库） |
| 数字 + 上下三角/左右箭头组 | 分页器/步进器 | `Pagination` / `InputNumber` |
| 开关状圆角长条 + 圆点 | 开关 | `<input type="checkbox" class="switch">` |

## 判断纪律

- **不确定就降级**：无法确认的复合结构，用语义化容器 `<section>`/`<div>` + `<!-- TODO: 语义待确认 -->`，并在页面分析文档中记录，不要硬猜成具体控件。
- **文本即数据**：设计稿中的示例文本（标题、表格行）应识别为 mock 数据，抽到 `<script setup>` 的响应式数据里，不硬编码进模板深处。
- **图标处理**：设计稿图标多为矢量组/图片，统一用占位（如 `<span class="icon">` 或 emoji 尺寸框）+ TODO，除非用户指定图标库。
- **表单聚合**：相邻的 label+输入控件组应聚合为 `<form>` 语义，为 Phase 7 的提交事件预留。
- 每处推断在 `artifacts/02-analysis/<画板>.md` 中记录「结构特征 → 推断 → 置信度」。
