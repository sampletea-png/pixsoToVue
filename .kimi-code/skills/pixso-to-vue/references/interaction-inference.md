# 交互与路由推断规则

设计稿没有原型连线，但多个画板之间**确实存在事件关系**（点按钮跳详情、Tab 切换、表单提交）。AI 必须推断这些关系并在 Phase 7 接线。每条推断必须标注置信度：**高 / 中 / 低**。

## 推断依据（按可信度排序）

1. **画板/区域命名**（最强信号）：画板名 `详情`、`登录`、`列表` 直接提示页面角色；`详情-点击后` 这类命名提示跳转结果。
2. **按钮/链接文案**：`查看详情` `编辑` `删除` `提交` `返回` `登录` —— 文案即事件。
3. **跨画板结构复用**：画板 B 中包含画板 A 列表项的展开版 → A 列表项点击 → B。
4. **元素同位置变化**：两个画板仅局部不同（弹窗出现/消失、Tab 高亮移动）→ 同一页面内的状态切换而非路由跳转。
5. **视觉惯例**：卡片/列表项可点击、logo 回首页、右上角头像出下拉。

## 常见模式 → 实现

| 模式 | 推断 | Phase 7 实现 |
| --- | --- | --- |
| 列表页 + 详情页 | 列表项点击 → 详情 | `router.push({ name: 'detail', params: { id } })` |
| 表单页（多个输入 + 提交按钮） | 提交 → 校验 → 成功反馈/跳列表 | `form.submit` → store action → router 或消息提示 |
| Tab 页签多画板（仅内容区不同） | Tab 切换 | 同一页面内 `v-model` 激活态，**不是路由** |
| 画板间仅浮层有无 | 弹窗打开/关闭 | `Dialog` + `v-model:visible` |
| 登录页 + 主页 | 登录成功 → 主页 | 表单提交 → `router.replace('/home')` |
| 分页器多画板 | 翻页 | `page` 响应式 + 数据重取（mock 则前端切片） |
| 空态/加载态画板 | 数据状态 | `v-if` 状态分支 |

## 路由 vs 页内状态（最容易判错的点）

- **整屏内容替换**（保留导航框架）→ 路由跳转。
- **局部变化**（弹窗、Tab、展开、高亮）→ 页内响应式状态。
- 判断不了就按「局部变化」处理（页内状态），并在分析文档标低置信度。

## 输出格式（写入 `artifacts/02-analysis/<画板>.md` 的交互推断表）

| 触发元素 | 推断事件 | 目标（路由/状态） | 置信度 | 依据 |
| --- | --- | --- | --- | --- |
| 列表项卡片 | click | `router.push('/detail/:id')` | 高 | 存在「详情」画板且结构为列表项展开版 |

## 低置信度处理

- Phase 7 实现为**合理默认行为** + 代码内 `TODO: 交互待确认`。
- 全部低置信度项汇总成清单，在 Phase 7 结束时一次性告知用户，不逐条打断。
